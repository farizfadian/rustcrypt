## 🎯 Project Summary (TL;DR)

**RustCrypt** is a Jasypt-like encryption library for Rust, the 5th member of a cross-language encryption family.

```

│   🦀 RustCrypt  github.com/farizfadian/rustcrypt   (Rust)       │
```

**GoCrypt is the reference implementation.** When in doubt, match GoCrypt byte-for-byte.
Never "improve" a wire format on your own: a value encrypted by any member must decrypt in every other member.

## 🏗️ Java Interop Context

Typical deployment: a Go or Rust API and a Java service (for example JasperReport for PDF/Excel) read the SAME encrypted config. Any Rust service in such a setup must use `JasyptEncryptor`.

```rust
// ✅ CORRECT when Java must read the value
let enc = JasyptEncryptor::new(password)?;

// ❌ WRONG - Java cannot read AES-GCM
let enc = Encryptor::new(password)?;
```

## 🔐 Three Encryptors

| Type | Algorithm | Java Compatible? | Notes |
|------|-----------|------------------|-------|
| `Encryptor` | AES-256-GCM | ❌ NO | family-internal, authenticated |
| `JasyptEncryptor` | PBEWithMD5AndDES | ✅ YES | Jasypt default, Java interop |
| `JasyptStrongEncryptor` | PBEWithHmacSHA256AndAES_256 (family format) | family only | see Known Issues |

## 📐 Wire Formats (MUST match GoCrypt exactly)

All outputs are **standard base64 with padding**. All outputs are wrapped as `ENC(<base64>)` by the `*_with_prefix` variants. Empty password → `Error::EmptyPassword`. Empty plaintext/ciphertext → `Error::EmptyValue`.

### `Encryptor` - AES-256-GCM (family-internal, NOT Java-compatible)

| Parameter | Default | Configurable |
|---|---|---|
| KDF | PBKDF2-HMAC-SHA256 | — |
| Iterations | `10000` | `with_iterations(n)` |
| Salt size | `16` bytes, random | `with_salt_size(n)` |
| Key size | `32` bytes (AES-256) | `with_key_size(16\|24\|32)` (returns `Result`) |
| Nonce | `12` bytes, random | — |
| AEAD | AES-GCM, tag 16 bytes appended to ciphertext, no AAD | — |
| **Output** | `base64( salt ‖ nonce ‖ ciphertext ‖ tag )` | |

Decrypt: reject if decoded length `< salt_size + 12`. Any GCM auth failure → `Error::DecryptionFailed` (no details leaked). Non-UTF-8 plaintext → `Error::DecryptionFailed`.

### `JasyptEncryptor` - PBEWithMD5AndDES (Java Jasypt default, ✅ compatible)

| Parameter | Value |
|---|---|
| KDF | PBKDF1 with MD5: `h = md5(password ‖ salt)`, then `h = md5(h)` repeated `iterations-1` more times (total `iterations` MD5 calls) |
| Iterations | `1000` (Jasypt default), `with_iterations(n)` |
| Salt size | `8` bytes, random |
| Key / IV | first 8 bytes of `h` = DES key, bytes 8..16 = IV |
| Cipher | DES-CBC, PKCS5 padding (block 8) |
| **Output** | `base64( salt ‖ ciphertext )` |

Decrypt: reject if decoded length `< 16` or ciphertext length not a multiple of 8 → `Error::InvalidJasyptData`. Invalid padding → `Error::DecryptionFailed`.

DES-CBC has no integrity check: a wrong password may yield garbage instead of an error (same caveat as the other 4 libraries; RustCrypt additionally rejects non-UTF-8 garbage).

### `JasyptStrongEncryptor` - "PBEWithHmacSHA256AndAES_256" (family format)

| Parameter | Value |
|---|---|
| KDF | PBKDF2-HMAC-SHA256, `iterations` = `1000` (`with_iterations`), derive **48 bytes** |
| Salt size | `16` bytes, random (`with_salt_size`) |
| Key / IV | derived[0..32] = AES-256 key, derived[32..48] = IV |
| Cipher | AES-256-CBC, PKCS7 padding (block 16) |
| **Output** | `base64( salt ‖ ciphertext )` |

Decrypt: reject if decoded length `< salt_size + 16` or ciphertext not a multiple of 16 → `Error::InvalidJasyptData`. Invalid padding → `Error::DecryptionFailed`.

⚠️ This is the format used by GoCrypt/PyCrypt/NodeCrypt/PHPCrypt and is self-consistent across the family, but it is **not byte-identical to Java Jasypt's real `PBEWithHmacSHA256AndAES_256`** (real Jasypt uses a random IV prepended: `salt ‖ iv ‖ ct`). **Match GoCrypt anyway.** Any move to the true Jasypt layout is a coordinated v1.1 across all five libraries.

### Shared helpers

```
ENC_PREFIX = "ENC("
ENC_SUFFIX = ")"
regex for scanning text: ENC\(([^)]+)\)
```

- `is_encrypted(&str) -> bool` - trimmed value starts with `ENC(` and ends with `)`
- `decrypt_prefixed(&str)` - trims whitespace, validates wrapper, decrypts inner
- `decrypt_all_in_string(&str) -> Result<String>` - replace every match; a failing match keeps the original text and the last error is returned after processing everything (GoCrypt semantics)
- `decrypt_all_in_string_lossy(&str) -> String` - never fails, failing matches kept verbatim (NodeCrypt/PyCrypt semantics; used by `rustcrypt decrypt-file`)
- `decrypt_map(&HashMap<String,String>)` - decrypt values that `is_encrypted`, pass others through; first error aborts with `Error::KeyDecrypt { key, source }`

## 📝 API Reference

```rust
use rustcrypt_jasypt::{Encryptor, JasyptEncryptor, JasyptStrongEncryptor, ConfigLoader,
                       StringEncryptor, Error, Result, is_encrypted};

// Create (builders return Self; with_key_size returns Result)
let enc = JasyptEncryptor::new(password)?.with_iterations(1_000);

// Encrypt/Decrypt (inherent methods; the trait is only needed for generic code)
let encrypted = enc.encrypt_with_prefix(plaintext)?;   // ENC(...)
let plaintext = enc.decrypt_prefixed("ENC(...)")?;

// Batch
let decrypted_map = enc.decrypt_map(&config_map)?;
let text = enc.decrypt_all_in_string(&config_text)?;

// Config
let loader = ConfigLoader::new(password)?;                                    // AES-256-GCM
let loader = ConfigLoader::with_encryptor(JasyptEncryptor::new(password)?);   // configs shared with Java
let config = loader.load_env_file(".env")?;
let cfg: MyStruct = loader.load_json("config.json")?;
loader.set_to_env(".env")?;
```

## 📌 MSRV & dependency pins

- `rust-version = "1.75"`. The 2025/2026 RustCrypto line (`aes 0.9`, `aes-gcm 0.11`, `cbc 0.2`, `des 0.9`, `cipher 0.5`, `md-5 0.11`, `sha2 0.11`, `pbkdf2 0.13`) needs Rust 1.85, so the crate uses `aes 0.8`, `aes-gcm 0.10`, `cbc 0.1`, `des 0.8`, `cipher 0.4`, `md-5 0.10`, `sha2 0.10`, `pbkdf2 0.12`, `rand_core 0.6`. Bumping MSRV to 1.85 unlocks the new line.
- `clap` must stay `4.5.x` (4.6 needs 1.85); `assert_cmd` ≥ 2.2 needs 1.85. Cargo.lock (v3) pins compatible versions; regenerate with `cargo generate-lockfile --config 'resolver.incompatible-rust-versions="fallback"'`.
- `serde_yaml` is intentionally NOT used (deprecated upstream; the YAML loader is a flat line parser like GoCrypt's).

## ⚠️ Known Issues

1. `JasyptStrongEncryptor` format ≠ real Java Jasypt strong format (see Wire Formats). Do not fix unilaterally.
2. `JasyptEncryptor`: DES/MD5 are weak; no integrity check (wrong password → error or garbage).
3. `ConfigLoader::set_to_env` mutates the process environment (single-threaded start-up only). Implemented with a documented `unsafe` block so the crate is ready for edition 2024.
4. `load_yaml` is a flat `key: value` parser (GoCrypt parity), nesting is flattened.
