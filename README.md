**Jasypt-like encryption library for Rust** - Encrypt your application configuration with the familiar `ENC(...)` pattern used in Spring Boot applications, and share it with Go, Python, Node.js, PHP and Java.

> **Made with ❤️ from Claude AI for Rust developers who need Jasypt**

---

## 🎯 Why RustCrypt?

If you are coming from the Java/Spring Boot world, or you run services in several languages that must read the *same* encrypted configuration, RustCrypt is for you! It provides:

- ✅ **Familiar `ENC(...)` pattern** - Just like Jasypt in Spring Boot
- ✅ **Cross-language** - Byte-compatible with GoCrypt, PyCrypt, NodeCrypt, PHPCrypt and Java Jasypt
- ✅ **Multiple algorithms** - From legacy Jasypt compatibility to modern AES-256-GCM
- ✅ **Pure Rust** - RustCrypto crates only; no OpenSSL, no C build step, DES works everywhere
- ✅ **Config loaders** - `.env`, YAML and JSON with automatic decryption
- ✅ **CLI tool included** - `rustcrypt` mirrors `gocrypt-cli`
- ✅ **Tested against GoCrypt** - golden vectors generated by the reference implementation

## 🚀 Quick Start

### Basic Encryption/Decryption

```rust
use rustcrypt_jasypt::Encryptor;

fn main() -> rustcrypt_jasypt::Result<()> {
    // Create encryptor with password (read it from the environment in real code)
    let enc = Encryptor::new("mySecretPassword")?;

    // Encrypt
    let encrypted = enc.encrypt_with_prefix("db_password_123")?;
    println!("{encrypted}"); // ENC(base64encodedvalue...)

    // Decrypt
    let decrypted = enc.decrypt_prefixed(&encrypted)?;
    println!("{decrypted}"); // db_password_123
    Ok(())
}
```

### Loading Encrypted Configuration

```rust
use rustcrypt_jasypt::ConfigLoader;

// .env file:
// DATABASE_HOST=localhost
// DATABASE_PASSWORD=ENC(AbCdEf123456...)

let loader = ConfigLoader::new(&std::env::var("RUSTCRYPT_PASSWORD")?)?;
let config = loader.load_env_file(".env")?;

println!("{}", config["DATABASE_PASSWORD"]); // actual_password
```

## 🔐 Encryption Algorithms

RustCrypt provides three encryptors for different use cases:

| Encryptor | Algorithm | Security | Java compatible? | Use Case |
|-----------|-----------|----------|------------------|----------|
| `Encryptor` | AES-256-GCM + PBKDF2-HMAC-SHA256 | ⭐⭐⭐⭐⭐ | ❌ No | **Recommended** when only family members read the value |
| `JasyptStrongEncryptor` | PBKDF2-HMAC-SHA256 + AES-256-CBC | ⭐⭐⭐⭐ | family format | Stronger Jasypt-style mode shared inside the family |
| `JasyptEncryptor` | PBEWithMD5AndDES | ⭐⭐ | ✅ Yes | Legacy Jasypt compatibility (Java) |

### Which encryptor should I use?

```rust
use rustcrypt_jasypt::{Encryptor, JasyptEncryptor, JasyptStrongEncryptor};

// ═══════════════════════════════════════════════════════════════════════════
// RECOMMENDED: only Rust/Go/Python/Node/PHP services read the value
// ═══════════════════════════════════════════════════════════════════════════
let enc = Encryptor::new(password)?;

// ═══════════════════════════════════════════════════════════════════════════
// The value is shared with Java Jasypt (default algorithm), e.g. a JasperReport service
// ═══════════════════════════════════════════════════════════════════════════
let enc = JasyptEncryptor::new(password)?;

// ═══════════════════════════════════════════════════════════════════════════
// Stronger Jasypt-style mode, shared inside the family
// ═══════════════════════════════════════════════════════════════════════════
let enc = JasyptStrongEncryptor::new(password)?;
```

**Rule of thumb:** when a Java service (for example JasperReport) reads the same `.env`, always use `JasyptEncryptor`. `Encryptor` values cannot be read by Java.

## 📖 Usage Guide

### 1. Configuration Files

#### .env File

```env
# config.env
DATABASE_HOST=localhost
DATABASE_PORT=5432
DATABASE_PASSWORD=ENC(AbCdEf123456...)
API_KEY=ENC(XyZ789...)
```

```rust
let loader = ConfigLoader::new(&password)?;
let config = loader.load_env_file("config.env")?;
println!("{}", config["DATABASE_PASSWORD"]); // decrypted value
```

#### YAML File (flat, same limitation as GoCrypt)

```yaml
# config.yaml
database:
  host: localhost
  password: ENC(AbCdEf123456...)
```

```rust
let config = loader.load_yaml("config.yaml")?;
println!("{}", config["password"]); // keys are flattened
```

#### JSON File (serde, nested objects and arrays)

```rust
use serde::Deserialize;

#[derive(Deserialize)]
struct Database { host: String, password: String }

#[derive(Deserialize)]
struct Config { database: Database, api_keys: Vec<String> }

let config: Config = loader.load_json("config.json")?;
println!("{}", config.database.password);
```

Every `ENC(...)` string at any depth is decrypted; strings that fail to decrypt are kept as-is.

#### Jasypt mode for files shared with Java

```rust
use rustcrypt_jasypt::{ConfigLoader, JasyptEncryptor};

let loader = ConfigLoader::with_encryptor(JasyptEncryptor::new(&password)?);
let config = loader.load_env_file(".env")?;
```

### 2. Set to Environment Variables

```rust
let loader = ConfigLoader::new(&password)?;
loader.set_to_env(".env")?; // load and export every pair (call during start-up)

let db_password = std::env::var("DATABASE_PASSWORD")?;
```

### 3. Decrypt Map

```rust
use std::collections::HashMap;

let mut config = HashMap::new();
config.insert("host".to_string(), "localhost".to_string());
config.insert("password".to_string(), "ENC(encrypted_value)".to_string());

let decrypted = enc.decrypt_map(&config)?;
println!("{}", decrypted["password"]); // plaintext
```

### 4. Decrypt All in String

```rust
let input = "\
DATABASE_HOST=localhost
DATABASE_PASSWORD=ENC(encrypted_value)
API_KEY=ENC(another_encrypted_value)
";

let decrypted = enc.decrypt_all_in_string(input)?;       // Err on the first failure (GoCrypt semantics)
let best_effort = enc.decrypt_all_in_string_lossy(input);  // keeps failing ENC(...) verbatim
```

### 5. Check if Value is Encrypted

```rust
use rustcrypt_jasypt::is_encrypted;

if is_encrypted(&value) {
    let decrypted = enc.decrypt_prefixed(&value)?;
}
```

### 6. Generic code

All encryptors implement the `StringEncryptor` trait:

```rust
use rustcrypt_jasypt::StringEncryptor;

fn decrypt_config<E: StringEncryptor>(enc: &E, value: &str) -> rustcrypt_jasypt::Result<String> {
    enc.decrypt_prefixed(value)
}

let boxed: Box<dyn StringEncryptor> = Box::new(JasyptEncryptor::new(&password)?);
```

## 💻 CLI Tool

```bash
cargo install rustcrypt-jasypt      # installs the `rustcrypt` binary
# or download a release archive from GitHub Releases
```

```bash
# Encrypt a value
rustcrypt encrypt -p mySecret -v "database_password"
# Output: ENC(base64value...)

# Decrypt a value
rustcrypt decrypt -p mySecret -v "ENC(base64value...)"
# Output: database_password

# Encrypt all KEY=VALUE values in a file
rustcrypt encrypt-file -p mySecret -i .env.plain -o .env.encrypted

# Decrypt all ENC(...) values in a file (omit -o or use "-" for stdout)
rustcrypt decrypt-file -p mySecret -i .env.encrypted -o .env.plain

# Use the Java Jasypt compatible algorithm
rustcrypt encrypt -p mySecret -v "secret" --jasypt

# Use the strong algorithm
rustcrypt encrypt -p mySecret -v "secret" --jasypt-strong

# Raw base64 without the ENC(...) wrapper
rustcrypt encrypt -p mySecret -v "secret" --no-prefix

# Use an environment variable for the password
export RUSTCRYPT_PASSWORD=mySecret
rustcrypt encrypt -v "secret_value"
```

The commands, flags, messages and exit codes mirror `gocrypt-cli`, `pycrypt` and `nodecrypt`.

## ☕ Cross-Language Compatibility

### Compatibility Matrix

```
┌─────────────────────────────────────────────────────────────────┐
│            ENCRYPT WITH → DECRYPT WITH                          │
├─────────────────────────────────────────────────────────────────┤
│ Java Jasypt (default)  → JasyptEncryptor           ✅ YES       │
│ GoCrypt JasyptEnc      → JasyptEncryptor           ✅ YES       │
│ PyCrypt JasyptEnc      → JasyptEncryptor           ✅ YES       │
│ NodeCrypt JasyptEnc    → JasyptEncryptor           ✅ YES       │
│ PHPCrypt JasyptEnc     → JasyptEncryptor           ✅ YES       │
│ GoCrypt Encryptor      → Encryptor                 ✅ YES       │
│ GoCrypt StrongEnc      → JasyptStrongEncryptor     ✅ YES       │
│ JasyptEncryptor        → Java Jasypt               ✅ YES       │
│ Encryptor              → Java Jasypt               ❌ NO        │
│ Java Jasypt (default)  → Encryptor                 ❌ NO        │
└─────────────────────────────────────────────────────────────────┘
```

### Example: encrypt in Go, decrypt in Rust

```go
// Go (GoCrypt)
enc, _ := gocrypt.NewJasyptEncryptor("sharedPassword")
value, _ := enc.EncryptWithPrefix("hello")   // ENC(sIAlbZnxY3KGqbnsHk+t2w==)
```

```rust
// Rust (RustCrypt)
use rustcrypt_jasypt::JasyptEncryptor;

let enc = JasyptEncryptor::new("sharedPassword")?;
let plaintext = enc.decrypt_prefixed("ENC(sIAlbZnxY3KGqbnsHk+t2w==)")?; // "hello"
```

```python
# Python (PyCrypt)
from pycrypt_jasypt import JasyptEncryptor
JasyptEncryptor(password="sharedPassword").decrypt_prefixed("ENC(sIAlbZnxY3KGqbnsHk+t2w==)")  # "hello"
```

```java
// Java (Jasypt)
StandardPBEStringEncryptor enc = new StandardPBEStringEncryptor();
enc.setPassword("sharedPassword");
enc.setAlgorithm("PBEWithMD5AndDES");
enc.decrypt("sIAlbZnxY3KGqbnsHk+t2w==");   // "hello"
```

**Requirement:** every side must use the same password and the same algorithm (and the same iteration count / salt size when customised).

### How compatibility is verified

- `tests/fixtures/gocrypt_vectors.json` holds values produced by GoCrypt v1.0.0 for all three modes (ASCII, punctuation, 200 characters, UTF-8 with emoji), plus fixed-salt vectors computed with GoCrypt's own KDF and cipher code. `cargo test` asserts that RustCrypt decrypts every one of them and reproduces the fixed-salt outputs byte-for-byte.
- `cargo test -- --ignored` (with `gocrypt-cli` on `PATH` or `GOCRYPT_CLI=/path/to/gocrypt-cli`) round-trips live in both directions.
- `scripts/cross-check.ps1` runs the same round trips against `gocrypt-cli`, `pycrypt` and `nodecrypt` when they are installed.

## ⚙️ Advanced Configuration

```rust
// AES-256-GCM
let enc = Encryptor::new(password)?
    .with_iterations(50_000)   // default: 10_000
    .with_salt_size(32)        // default: 16
    .with_key_size(32)?;       // 16 = AES-128, 24 = AES-192, 32 = AES-256 (default)

// Jasypt compatible: match the Java side's keyObtentionIterations
let enc = JasyptEncryptor::new(password)?
    .with_iterations(2_000);   // default: 1_000

// Jasypt strong
let enc = JasyptStrongEncryptor::new(password)?
    .with_iterations(5_000)    // default: 1_000
    .with_salt_size(32);       // default: 16
```

Parameters are not stored in the ciphertext, so both sides must use the same values.

## 🛡️ Security

### Algorithm Comparison

| Algorithm | Cipher | Key Derivation | Integrity | Security |
|-----------|--------|----------------|-----------|----------|
| `Encryptor` | AES-256-GCM | PBKDF2-HMAC-SHA256 (10 000) | AEAD tag | ✅ Strong |
| `JasyptStrongEncryptor` | AES-256-CBC | PBKDF2-HMAC-SHA256 (1 000) | none (padding only) | ✅ Good |
| `JasyptEncryptor` | DES-CBC | PBKDF1-MD5 (1 000) | none (padding only) | ⚠️ Legacy |

### Best Practices

1. **Never hardcode passwords** - Use environment variables (`RUSTCRYPT_PASSWORD`)
2. **Rotate passwords regularly**
3. **Use strong passwords** (minimum 16 characters)
4. **Store encrypted config in version control**, not plaintext
5. **Use `Encryptor` unless Java must read the value** - it is the only mode with authentication

Please report vulnerabilities as described in [SECURITY.md](SECURITY.md).

## ⚠️ Known Issues

- **`JasyptStrongEncryptor` is not byte-identical to Java Jasypt's `PBEWithHmacSHA256AndAES_256`.** Real Jasypt prepends a random IV (`salt ‖ iv ‖ ciphertext`); the family format derives the IV from PBKDF2 (`salt ‖ ciphertext`). It is fully interoperable with GoCrypt, PyCrypt, NodeCrypt and PHPCrypt, and will only change in a coordinated release of all five libraries.
- **`JasyptEncryptor` uses DES and MD5**, which are weak by modern standards, and DES-CBC has no integrity check: decrypting with a wrong password usually fails with `Error::DecryptionFailed` but can occasionally return garbage. Use it for Java compatibility only.
- **`ConfigLoader::set_to_env` mutates the process environment.** Call it during single-threaded start-up, before other threads read environment variables.
- **`load_yaml` is a flat line parser** (`key: value`), the same simplification as GoCrypt. Use a YAML crate plus `decrypt_map` for complex documents.

## 📚 API Reference

Full documentation: <https://docs.rs/rustcrypt-jasypt>

```rust
// Constructors (all return Result; empty password -> Error::EmptyPassword)
Encryptor::new(password)             .with_iterations(u32) .with_salt_size(usize) .with_key_size(usize)?
JasyptEncryptor::new(password)       .with_iterations(u32)
JasyptStrongEncryptor::new(password) .with_iterations(u32) .with_salt_size(usize)

// Methods (inherent on every encryptor and on the StringEncryptor trait)
fn encrypt(&self, plaintext: &str) -> Result<String>                 // base64
fn encrypt_with_prefix(&self, plaintext: &str) -> Result<String>     // ENC(base64)
fn decrypt(&self, encoded: &str) -> Result<String>
fn decrypt_prefixed(&self, value: &str) -> Result<String>
fn decrypt_all_in_string(&self, input: &str) -> Result<String>
fn decrypt_all_in_string_lossy(&self, input: &str) -> String
fn decrypt_map(&self, map: &HashMap<String, String>) -> Result<HashMap<String, String>>

// Helpers
fn is_encrypted(value: &str) -> bool
const ENC_PREFIX: &str = "ENC(";
const ENC_SUFFIX: &str = ")";

// ConfigLoader (feature "config", default)
ConfigLoader::new(password) -> Result<ConfigLoader<Encryptor>>
ConfigLoader::with_encryptor(enc) -> ConfigLoader<E>
fn load_env_file(&self, path) -> Result<HashMap<String, String>>
fn load_yaml(&self, path) -> Result<HashMap<String, String>>
fn load_json<T: DeserializeOwned>(&self, path) -> Result<T>
fn decrypt_json_value(&self, value: &mut serde_json::Value)
fn set_to_env(&self, path) -> Result<()>

// Errors (thiserror, #[non_exhaustive])
Error::{EmptyPassword, EmptyValue, InvalidEncFormat, InvalidJasyptData, DecryptionFailed,
        Base64(_), Io(_), Json(_), KeyDecrypt { key, source }, InvalidParameter(_)}
```
